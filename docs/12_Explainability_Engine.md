# 1. Purpose

The Explainability Engine (EE) provides transparent, human-readable reasoning for every decision generated by SENTRA.

Unlike traditional "black-box" AI systems, SENTRA SHALL provide clinicians with understandable evidence supporting every recommendation, alert, and patient priority.

The Explainability Engine SHALL NOT modify predictions.

It SHALL explain them.

---

# 2. Design Philosophy

Clinicians must understand why SENTRA generated a recommendation.

Every Priority Score must be traceable back to its contributing evidence.

```
Sensor Data

↓

Feature Extraction

↓

Clinical Rules

↓

Subsystem Scores

↓

Priority Engine

↓

Explainability Engine

↓

Dashboard
```

Every decision SHALL be reproducible.

---

# 3. Responsibilities

The Explainability Engine SHALL

• Explain every priority decision

• Display contributing physiological evidence

• Rank contributing subsystems

• Display triggered clinical rules

• Summarize trends

• Report confidence

• Support auditability

• Maintain complete transparency

---

# 9. Evidence Ranking

Each evidence source receives an influence score.

Example

| Evidence | Influence |
|-----------|-----------|
| Persistent Tachycardia | 38% |
| Respiratory Risk | 25% |
| Baseline Deviation | 17% |
| Trend | 12% |
| Context | 8% |

Evidence SHALL be sorted from greatest to least contribution.

---

# 10. Primary Explanation

The highest weighted contributor becomes the Primary Reason.

Example

```
Primary Reason

Persistent Tachycardia
```

Secondary contributors remain available.

---

# 11. Secondary Reasons

Multiple abnormalities often contribute to patient deterioration.

Example

```
Primary

Persistent Tachycardia

Secondary

Increasing Respiratory Rate

Reduced HRV

Elevated Temperature
```

The engine SHALL provide all significant contributors.

---

# 12. Confidence Summary

Every explanation SHALL include confidence.

Example

```
Confidence

94%

Signal Quality

Excellent

Sensor Coverage

Complete
```

Low confidence SHALL be clearly communicated.

Personalized monitoring is a core SENTRA feature.

Example

```

72 BPM

Current HR

118 BPM

Deviation

+46 BPM
```

Deviation shall always reference the patient's own baseline rather than generic population averages.

# 16. Subsystem Summary

Subsystem scores SHALL be displayed independently.

Example

92

Respiratory Risk

76

Temperature Risk

41

# 17. Context Explanation

Physiological measurements SHALL always be interpreted within patient context.

Example

```
Heart Rate

158 BPM

Activity

Running

↓

Expected Physiological Response
```

```
Heart Rate

158 BPM

Activity

Sleeping

↓

Unexpected Physiological Response
```

Supported contextual information

• Resting

• Walking

• Running

• Sleeping

• Recovery

• Unknown

The Explainability Engine SHALL communicate how context influenced the Priority Score.

# 19. Natural Language Summary

The Explainability Engine SHALL convert technical outputs into concise clinician-readable summaries.

Example

```
Patient priority increased from WATCH to HIGH PRIORITY due to persistent tachycardia, worsening respiratory rate, and significant deviation from baseline. Confidence remains high with excellent signal quality.
```

Summaries SHALL avoid technical jargon whenever possible.

# 21. Explainability Levels

Different users require different levels of explanation.

### Level 1 – Summary

Single sentence overview.

### Level 2 – Clinical

Evidence and contributing physiological systems.

### Level 3 – Technical

Complete algorithmic reasoning, subsystem outputs, weighting, and confidence calculations.

Future versions may support user-selectable explainability levels.

# 25. Error Handling

The Explainability Engine SHALL remain operational even when evidence is incomplete.

Possible Failures

• Missing subsystem output

• Missing baseline

• Incomplete trend history

• Confidence unavailable

Recovery Strategy

• Explain available evidence

• Report unavailable components

• Preserve transparency

The engine SHALL never fabricate missing information.

---

# 26. Performance Requirements

The Explainability Engine SHALL

• Execute in real time

• Produce deterministic outputs

• Support concurrent patients

• Generate clinician-readable summaries in under 100 ms

Target latency

```
<100 milliseconds
```

per explanation request.

# 31. Summary

The Explainability Engine provides the transparency layer that distinguishes SENTRA from traditional black-box AI systems.

By transforming Priority Engine outputs into structured evidence, ranked physiological contributors, trend analyses, baseline comparisons, confidence summaries, and natural language explanations, the Explainability Engine ensures every recommendation is understandable, auditable, and clinically interpretable.

This architecture enables clinician trust, supports regulatory compliance, facilitates post-event review, and provides the foundation for safe deployment of SENTRA in real-world healthcare environments.
